## 2. 冻结最小规格

### 硬件与算子

选择“仍能展示算子行为的最小规格”，不是把所有维度设为 1。

| 项目 | 冻结规格 |
|---|---|
| CPU | VexRiscv RV32IM，沿用现有 4 KiB cache profile；SPEC 分别列出实际 I/D cache 容量 |
| GPU | Vortex，1 core、2 warps、4 threads、无 L2；保留该配置实际需要的 L1、local memory 和 adapter |
| 加速器 | 串行 P1/P2/P3，沿用已验证的时序切分，不启用晋升优化 |
| P1 | 1 head；NOPE/ROPE/index/value 维度为 8/4/8/8；Top-K 容量 4 |
| P2 | 同一注意力数值维度；split 为 1、2、4 |
| P3 | hidden/intermediate 最大均为 16；2 个路由专家，激活 1 个；Nano 另保留 1 个共享专家 |
| 普通算子用例 | batch=1，query/rows 为 1 或 2，KV 长度为 1、2、4、5、8 |
| 地址边界 | page size 为 1、4；保留跨页、尾页、非连续页及 padding |
| Nano 容量 | context=32；不再运行大规模 trace |
| 工艺与时钟 | SKY130HD，10 ns／100 MHz，不降频换 PASS |

CPU/GPU 使用仓库已有的最小冻结配置，避免为了继续缩核重新开发处理器。该选择不等于理论上的最小芯片。

仅建立一个 `mini` profile：**CPU 一份、GPU 一份、三个加速器各一份，共五份唯一物理实现，生成九个算子引用**。只有实际硬件、配置和网表完全一致时才共享；软件和活动功耗仍分别绑定。

### 数值合同

不同时引入 INT4 或降低累加位宽，优先减小数据规模：

- 输入/权重 INT8，完整范围 `[-128,127]`；普通随机样本用 `[-8,7]`，极值另测。
- 点积 INT32；现有更宽的归并、乘积及除法中间值保持不变。
- BF16 语义输入校准范围 `[-16,16]`；输出 BF16-RNE。
- score delta 保留 Q5.11 的 `[-16,0]` 合同，exp 保留 Q1.15。
- scale 为有限正 FP32，正常范围 `[2^-16,2^16]`。
- 路由权重范围 `[0,1]`。
- INT8 重量化执行 RNE，再饱和。
- bit-exact golden 为硬件正确性的主判据；FP32 语义参考另行报告量化误差，不能混作同一种 delta。

SPEC 必须同时列出主机配置、虚拟硬件配置、算子合法范围、内部位宽、内存布局、时钟和工具版本。

### 极小 NanoChat

新增独立的小模型，不直接裁剪旧 checkpoint 后沿用旧质量报告：

- 1 layer、hidden=16、1 head、intermediate=16。
- 2 个路由专家、激活 1 个、1 个共享专家。
- 字符词表容量 256，context=32，最多生成 12 个 token。
- 限定问候、自我介绍、天气诚实回退、简单固定算术四类问题。
- 使用真正的逐 token 模型推理；禁止运行时问题—答案查表或硬编码答案。
- 使用 CPU 训练与导出，固定训练 seed=1；学生端只运行已交付 checkpoint。
- 固定训练、验证和测试集合，精确问题去重；“今天天气怎么样？”只进入测试集。
- FP32→INT8 checkpoint、校准样本、tokenizer、镜像和导出步骤全部记录 SHA。
- 三平台执行同一份测试问题，保存完整 token 序列、文本及 SHA；限定问答全部通过才接受。

旧模型具有固定大小的额外分类/嵌入表，因此不能仅修改 hidden 就宣称完成模型缩减。新小模型的实际参数数量和每类权重大小必须从导出文件统计。

## 3. 测试、golden、实际结果和 seed 汇总

### 固定用例矩阵

每个算子先定义以下 12 个专属 case：

| 编号 | P1 | P2 | P3 |
|---|---|---|---|
| 01 | Q=1、KV=1、K=1 | length=1、split=1 | rows=1，单激活专家 |
| 02 | KV=4，完整一页 | length=2、split=2 | rows=2，分别路由两专家 |
| 03 | KV=5，跨页尾部 | length=4、split=1 | rows=2，集中同一专家 |
| 04 | Q=2、KV=5，因果掩码 | length=5、split=2 | 未激活专家权重注入毒值 |
| 05 | 同尺寸，非因果 | length=8、split=4 | 路由分数平局 |
| 06 | 分数全相等，验证稳定 Top-K | 最大值出现在后一分块 | route weight=0 |
| 07 | 最大分数出现在最后位置 | exp 截断边界 | route weight=1 |
| 08 | K 大于有效 KV 长度 | 分块执行顺序变化，保持规定归并语义 | route weight=0.5 |
| 09 | 非连续页表 | 非连续页表 | 交换 token 行，检查输出对应关系 |
| 10 | padding 中注入毒值 | padding 中注入毒值 | 正负输入与权重抵消 |
| 11 | Q=2、KV=8，随机数值 | length=0，预期错误 | 越界 expert ID，预期错误 |
| 12 | Q=0，预期错误 | split=3，预期错误 | hidden=0，预期错误 |

每个算子另外加入公共 case：

- 全零、全 `-128`、全 `127`、正负交替。
- scale 下界、上界。
- RNE 正负半值及奇偶商；饱和上下界和刚越界。
- 无效 scale：零、负数、NaN、正负 Inf 分别作为子 case。
- DMA 错误、输入背压、输出保持、运行中复位及复位后再次执行。

边界组必须展开成具独立 ID 的子 case，不允许用一个总体 PASS 掩盖未执行分支。复位、错误和状态测试记录预期事件/状态及实际事件/状态，不计算无意义的数值平均。

### Seed 与输入生成

- **每个展开后的 case 均执行 seed=1–10，三平台使用完全相同的输入文件。**
- 固定并记录 PRNG 算法、版本、seed、输入生成规则及实际输入 SHA。
- 极值 case 不因 seed 改掉边界值；seed 只改变合法的数据排列、地址或背压序列，并在记录中说明。
- 运行前生成并冻结 golden；设备只接收输入，不能读取 golden 输出。
- CPU/GPU 现有数值 signature 不够用于本次交付，必须导出完整结果数组；不能把 checksum 相同替代逐元素比较。

### 每条记录及统计

每个 `platform/operator/case/seed` 保存：

`规格与输入 → golden 原始位模式及数值 → actual 原始位模式及数值 → 每元素 signed delta/absolute delta → 不匹配位置 → 状态与性能计数 → 来源及 SHA。`

对每个 case 的 10 个 seed：

- 保存逐元素 golden 均值、actual 均值及两者差值。
- 同时保存逐 seed 的最大绝对误差、MAE、RMSE、bit mismatch 数和 PASS/FAIL。
- 汇总最大误差、平均绝对误差、失败 seed 列表。
- cycles/instructions/DMA/cache 分别记录原始值及均值，不用主机墙钟代替硬件计数。
- **任何一个 seed 失败，则该 case 失败；平均值相等不能抵消失败。**

提供 JSON/NPZ 原始数据、CSV 汇总和离线 HTML 报告。点击任何汇总项，都能查看对应的输入、golden、actual 和 delta。

## 4. 物理证据、学生资源和工作包

### 物理验收

五份唯一实现均需真实综合、布局布线和功耗分析：

- WNS≥0、DRC=0、antenna=0，宏 pin 可访问。
- 保留最终 DEF、网表、SDC、寄生参数、工具日志及配置 SHA。
- 功耗必须来自该网表的实际活动；记录采样区间、工作负载、频率、电压、温度、活动覆盖率及未标注信号比例。
- CPU/GPU 的 P1/P2/P3 可以共享物理网表，但不能直接共享不同负载的功耗数值。
- 每个算子的功耗性能板覆盖 seed 1–10，记录逐 seed 和平均值。
- 物理证据不包含板级、主机或完整外部 DRAM 功耗；报告明确边界。
- 旧物理结果仅在完整输入及硬件边界一致时复用，不能给新小规格贴旧 PASS。
- （2026-10-11 补充）一份物理实现可由层次化结构组成：GPU 采用 4 个硬化分块（各自独立布局布线，DRC/antenna/宏 pin/电源网格逐块验收）加顶层组装；其 WNS≥0 以组装后**全芯片 STA**（顶层网表 + 4 个分块最终网表与各自 SPEF，不用抽象时序模型）签核，分块边界预算仅为内部手段。CPU 的 25 个 ROM bank 同样作为硬化分块逐个验收后由顶层集成。

### 学生机器

以 **x86-64、16 GB 内存、无独显的普通笔记本**为支持目标：

- Ubuntu 24.04；Windows 使用 WSL2。
- 默认最多 2 个工作线程，同时只运行一个重型仿真或物理任务。
- 在 2 vCPU、8 GiB 任务内存限制下执行验收，记录峰值内存、临时磁盘和耗时；不能仅靠开发机容量推断兼容。
- 不使用 CUDA、实体 GPU、云端训练或远程仿真作为必需条件。
- GPU 功能来自 Vortex SimX；RTL 协议、计数和活动来自 RTLSIM。
- 提供无需大型 EDA 环境的报告查看/证据校验入口，以及安装依赖后的完整重跑入口。
- 依赖路径可配置，不能要求学生拥有开发机的 C/D/E 盘布局。

### 包内容和大小

使用明确白名单打包，不使用现有“复制整个仓库”的发布脚本。

包含源码、SPEC、冻结 manifest、模型与 tokenizer、全部输入/golden/actual/delta、五份物理证据、九个 baseline 汇总、安装说明、版本锁和 SHA 清单。四层候选只保留结构及 `NOT_RUN` 标识。

不包含软件安装包、Python 环境、容器镜像、编译缓存、训练优化器状态或整个历史证据库。PDK/标准单元库等依赖通过锁定清单安装，合法可分发的项目专用宏视图按需要收录并附许可。

- 压缩包目标≤1 GiB，解压后目标≤3 GiB；最终必须报告实测字节数。
- DEF/SPEF/日志压缩，避免重复拷贝共享物理文件；学生包不包含可重建的中间 ODB，原工作区不删除它们。

### 已确认的实施决策

- **GPU 层次化实现**：4 个硬化分块 + 顶层；签核见第 4 节补充条款。
- **OpenROAD 补丁**：详细布线一次保留整批（1024 个）布线单元导致峰值内存与线程数无关；`third_party/patches/openroad-drt-batch-size.patch` 增加可选环境变量 `STUDENT_MINI_DRT_BATCH_SIZE`（默认行为不变），受限运行取 64，峰值内存约减半且布线结果一致。安装脚本在编译前应用该补丁，版本锁记录其 SHA。
- **并行执行**：开发机并行运行多个受限任务（见第 5 节第 4 步调整）。
- **宏引脚审计**：宏的接入点由详细布线按“唯一实例模式”存于宏母版，实例级首选接入点列表对宏恒为空，不能作为接入判据；改为几何判据——同一网络的导线或通孔在同一金属层与引脚形状重叠才算接入并布通；无其他端点的输出引脚（无负载）不需布线，单独计数报告。`--reaudit` 只在全部非审计输入 SHA 不变时，对已完成运行的结果重做审计与签核检查。
- **GPU 宏重定位**：分割前把 icache 数据 SRAM 0–4 从右上块移到左上块第二列（带宏重叠检查），使半周期读路径留在块内；相邻宏之间或宏与核心边缘的窄条行被完全切除（防止修复缓冲器无法合法化）。
- **门级重放比较起点**：输出在时钟低电平采样，第 0 周期位于第一个上升沿之前（寄存器为未定义的上电值），比较从第 1 周期（复位有效下第一个时钟沿之后）开始；功耗窗口（流量计数器释放→捕获）比固件周期计数多固定 95 个插桩周期，作为记录字段保留。
- **GPU 布线后 ECO**（`--eco-from`，2026-10-13）：在已布线分块上做时序修复（仅尺寸/引脚交换/插缓冲，不改逻辑）、对内部寄存器路径未能修复的捕获寄存器插入时钟延迟单元（有用偏斜，须保持出向建立与保持裕量），只重布改动的网络；每轮按 ORFS 同样的 RCX 提取→写回 SPEF 计时，DRC 0 且不新增保持违例才接受。分块 SDC 只含块间预算，块的芯片端口（如 rst_ni）在 ECO 修复与计时中按 GPU 约束加顶层走线余量约束（只收紧修复目标）。签核仍是不变 GPU 约束下的全芯片 STA。
- **顶层复位改线**：分割把 rst_ni 串行穿过四块（纯缓冲/反相链）。顶层准备脚本从各块最终网表追踪此类“芯片输入的纯穿通”，在顶层直接接芯片输入（奇数次反相时经一个顶层反相器），逻辑等价，改线清单写入 `feedthrough_rewiring.json`；功耗脚本按同一规则复算并要求逐字一致。
- 预计剩余时间约 12–20 小时（主要风险：顶层首次完整运行、全芯片 STA 残余违例、GPU 门级功耗重放）。
